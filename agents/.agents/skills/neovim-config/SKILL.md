# Neovim configuration

Change the config, then prove it still starts. A config that errors on startup
silently drops every setting after the error, which looks like "the plugin is
broken".

## Layout

A config is `init.lua` plus a `lua/` tree:

```
init.lua                  entry point, requires config modules
lua/config/init.lua       loader: options, keymaps, diagnostics, autocmds, lazy
lua/config/*.lua          one concern per file
lua/config/lazy.lua       lazy.nvim bootstrap + spec
lua/plugins/*.lua         one plugin topic per file, returns a spec list
lsp/<server>.lua          native LSP config, returned as vim.lsp.Config
lua/.luarc.json           lua_ls settings for editing this config
.stylua.toml              formatter config
lazy-lock.json            pinned plugin revisions (generated)
```

Rules:

- `init.lua` stays a one-liner (`require("config")`). Real settings live in
  `lua/config/`.
- One plugin per file where the plugin has any config, grouped by topic
  (`lsp.lua`, `treesitter.lua`, `git.lua`), not alphabetically by repo name.
- Never edit `lazy-lock.json` by hand. It is regenerated by `:Lazy sync`.
- If the repo keeps several configs (a work variant, a minimal variant), change
  the canonical one first, then port. Do not let a third fork appear.

## Add a plugin

```lua
-- lua/plugins/git.lua
return {
  {
    "lewis6991/gitsigns.nvim",
    event = "BufReadPre",           -- load lazily unless it must be early
    opts = {
      signs = { add = { text = "+" } },
    },
  },
}
```

- Default to lazy: `event`, `cmd`, or `ft`. Use `lazy = false` only for
  colorschemes and anything that must exist before `VeryLazy`.
- Prefer `opts = {}` over `config = function()`; lazy.nvim calls `setup(opts)`
  for you. Use `config` only when setup needs imperative code.
- Add keymaps through the spec (`keys = { ... }`) when the plugin binds them, so
  the plugin loads on first press.
- After adding or changing a plugin, run `:Lazy sync` and inspect
  `:checkhealth <plugin>` before assuming your config is at fault.

## Add a language server (Neovim 0.11+)

Native LSP, no `nvim-lspconfig` plugin needed for the plumbing:

```lua
-- lsp/terraformls.lua
---@type vim.lsp.Config
return {
  cmd = { "terraform-ls", "serve" },
  filetypes = { "terraform", "tf" },
  root_markers = { ".terraform.lock.hcl", ".git" },
  settings = {},
}
```

Then enable it once the server binary exists on `PATH`:

```lua
vim.lsp.enable("terraformls")
```

- `root_markers` decides project scope; a wrong marker makes the server attach to
  a directory it cannot resolve imports from. Check with `:LspInfo`.
- Verify the binary exists before debugging config: `command -v terraform-ls`.
- A server that never attaches is usually `filetypes` (run `:set filetype?`) or a
  missing root marker, not the settings.

## Keymaps

```lua
vim.keymap.set("n", "<leader>f", function()
  require("conform").format({ lsp_fallback = true })
end, {desc = "Format file"})
```

- Always pass `desc`. It feeds which-key, `:map` listings, and the agent's
  understanding of the config.
- `vim.keymap.set` is not recursive and does not need `noremap`.
- Leader is `<space>` in this setup; define mappings in `lua/config/keymaps.lua`
  unless they belong to a plugin.

## Validate

Run all of these after a change, in this order:

```bash
stylua --check .                                  # formatting
nvim --headless "+checkhealth vim.lsp" +qa        # LSP health report
nvim --headless "+Lazy! sync" +qa                 # plugins resolve and install
nvim --headless "+lua vim.print('ok')" +qa        # startup completes
```

- Startup errors are printed to stderr with "Error detected while processing".
  Read them; do not assume a zero exit status means a clean start.
- Then open Neovim interactively for anything visual: colorscheme, signs, folds,
  diagnostics, and which-key. Headless checks cannot see those.
- `:messages` after startup shows errors that scrolled past.
- `nvim -l script.lua` runs a Lua script without a UI — useful for testing a pure
  helper module (`vim.fn` and `vim.api` are available, `vim.ui` is not).

## Common failures

| Symptom | Usual cause |
| ------- | ----------- |
| Setting has no effect | An error earlier in startup aborted the rest of the file |
| `attempt to index a nil value` in `config` | Plugin's `setup()` called before it loaded; use `opts` or an `event` |
| Plugin loads but does nothing | `opts` passed to a plugin whose `main` differs; check `config` key |
| LSP never attaches | Wrong `filetypes` or `root_markers`; missing server binary |
| Formatting differs between editors | `stylua` not reading the repo's `.stylua.toml`; pass the path explicitly |
| `vim.loop` deprecation warning | Use `vim.uv` on 0.10+ |

## Formatting config (this dotfiles repo)

`nvim/.config/nvim/.stylua.toml` sets `syntax = "Luau"`, 80 columns, 2-space
indent, `AutoPreferDouble` quotes, no space after function names, and no
require sorting. Format with `stylua <config-dir>` from the repo root; do not
hand-wrap lines.
